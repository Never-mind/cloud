# 潜在客户

业务伙伴 → 潜在客户。支持登记公司名称、国家、联系人、电话、邮箱、税号、地址、来源、负责人、下一次跟进日期和备注；详情支持跟进记录与附件资料。

页面采用与客户管理一致的主从档案表单：点击“新增潜在客户”进入完整建档页，上方为基础资料主表，下方为跟进记录和附件明细表。顶部统一提供修改、保存、取消和转为客户操作；“基础资料 / 跟进记录 / 附件”导航可定位各分区。修改主表时先保存或取消，再操作从表，避免丢失尚未保存的内容。新增跟进在从表下方填写，保存后同步更新主表的跟进状态与日期。返回列表保留查询条件和页码。

此次主从表单调整无需新增数据库字段；沿用已部署的潜在客户表和权限。

状态为待联系、跟进中、暂缓、已转化、已终止。公司名称为建档必填项；转化前可维护信息。已终止记录需恢复跟进后再转化。

“转为客户”提供两种处理方式：

- 新建客户：确认客户全称、税务资料、地址和默认开票账期（默认30天，允许0天），生成现有 `customN` 格式的客户编码，档案启用，联系人同步到客户联系人表。
- 关联已有客户：按名称、客户编码或税号搜索启用的客户，直接建立关联，不覆盖其现有资料。

新建时会对税号和中英文公司全称进行大小写、全半角及标点空格归一化查重。遇到匹配项会阻止重复创建，并提示关联已有客户。简称不作为强制查重依据。

转化使用数据库事务及跨记录锁；重复提交返回已建立的客户关联。资料编辑和转化使用版本检查，防止覆盖并发修改。转化后原记录、跟进历史、附件只读保留；客户档案增加“潜在客户来源”入口，具有潜在客户查看权限的用户可打开原记录。附件继续存放于原潜在客户，避免重复文件和复制后的资料不一致。

权限沿用业务伙伴权限体系：新增、修改、删除分别控制建档、编辑/跟进、删除；“确认”权限控制转化，转化和搜索要求客户查看权限，新建客户额外要求客户新增权限。转化操作及编辑记录写入操作日志。删除未转化记录前需先清理附件。

## 部署

```powershell
npm run schema:prospects
npm run schema:prospects -- --apply
npm run build
# 按现有进程管理方式重启服务
```

迁移可重复执行：新增 `merge_common_prospects`、`merge_common_prospect_followups`、`merge_common_prospect_conversion_lock` 三张表；如果客户表尚无 `paymentTermDays` 则增加可空字段。不会把历史客户反向生成潜在客户，也不会修改已有客户的业务资料。执行前自动备份相关表结构到 `backup/prospects/`。

这项功能无需后台定时脚本。迁移完成并重启新版本后即可使用。

验证覆盖：新建和跟进、搜索与筛选、联系人/账期带入、保留附件历史、同单重复及并发提交、跨潜在客户同税号并发拦截、已有客户关联、已转化只读、乐观锁冲突、故障事务回滚与权限路由。
