# 自动同步运行规则

## Frappe 需求单

常驻 Next 后端启动 5 秒后检查一次，之后默认每 1800 秒同步；密码登录和飞书登录成功后通过 Next `after` 在响应完成后触发额外同步，不阻塞登录，不在登录失败或普通页面刷新时执行。

登录触发默认全站共享 300 秒冷却。同步函数持有现有数据库命名锁，在锁内检查最近一次非试运行记录（成功、失败及进程退出留下的运行记录均参与冷却）。多账号、多后端与手动同步不会并发抓取；正在运行则复用/跳过，最近已同步则按剩余时间安排下一轮，不新建空跑日志。同步用独立数据库连接持锁，避免应用连接池只有一个连接时阻塞其他查询。同步失败保留原有运行日志，后续自动重试。

配置（秒）：

```dotenv
FRAPPE_API_BASE_URL=https://your-frappe-host
FRAPPE_API_TOKEN=your-token
FRAPPE_DEMAND_AUTO_SYNC=1
FRAPPE_DEMAND_AUTO_SYNC_INTERVAL_SECONDS=1800
FRAPPE_DEMAND_SYNC_ON_LOGIN=1
FRAPPE_DEMAND_LOGIN_SYNC_COOLDOWN_SECONDS=300
```

启动日志 `[frappe-demand-auto-sync] enabled; interval=1800s; login=true; loginCooldown=300s; firstRun=5s` 表示已启用。测试、构建、不配置 Frappe 密钥或显式关闭时不启动。需求同步映射页面“最近同步结果”显示定时/登录/手动来源及失败原因；原有映射、已存在跳过、删除抑制和变更待核对规则沿用。无需新增表字段或另外注册计划任务。旧的 Windows 注册脚本及 `npm run sync:frappe-demands` 作为外部调度/人工入口保留；启用内置同步时不必重复配置它们。

## 飞书审批查询范围

| 通道 | 自动/批量候选 | 退出条件 | 批量上限与排序 |
| --- | --- | --- | --- |
| 开票 | pending/returned，或 approved 且尚未登记或仍有处理错误 | 已通过且已登记、无错误；驳回/撤回 | 内置每批 20，最久未查询优先，距离上次查询至少 60 秒 |
| 付款 | pending/returned，或上次同步/回填失败 | 终态且本地付款回填成功、无错误 | 后台默认每分钟、每批 30；页面打开也可触发，最久未查询优先 |

开票不能仅查“审批中”：财务可能在审批通过后才上传原件，必须继续追踪到登记完成。已完成历史发票不再每日查询；指定实例的手动复查仍可读取后补附件。付款逐条隔离错误，先成功回填来源，再记录审批终态，防止失败后永久退出队列。`backfill-cost-payment-confirmed.ts` 是人工历史到账日期补录脚本，不属于常规自动查询。

需求同步、开票和付款后台轮询都由运行中的服务执行，关闭浏览器不影响；停止服务或电脑关机则停止。生产服务器部署本版本、配置对应连接凭据并保持后端运行后即可自动执行，无需另加计划任务。三类同步分别使用数据库互斥锁。

## 付款后台定时同步

在常驻 Next 后端启动 5 秒后执行首轮，此后默认每轮完成后等待 60 秒再执行。覆盖算力采购付款、华为云供应商付款及集采项目付款，沿用同一付款审批同步服务与原有回填规则。

```dotenv
FEISHU_PAYMENT_AUTO_SYNC=1
FEISHU_PAYMENT_AUTO_SYNC_INTERVAL_SECONDS=60
```

间隔以秒计，支持 60～86400 秒；例如 300 为每 5 分钟、1800 为每半小时，修改后需重启后端。未配置间隔或值无效时使用 60 秒。有飞书应用凭据时默认启用；显式设为 0、false 或 off、构建或测试阶段均不启动。

页面刷新与后台轮询共用数据库锁，拿到锁后才筛选待处理记录；同一审批距离上次查询至少 60 秒。多人打开列表、多服务同时运行、请求较慢时均不会并行处理同一批。每批最多 30 条，按最久未查询优先，已完成且回填成功的历史记录退出队列。失败写入 `syncError` 并在后续轮次重试。

启动日志 `[payment-auto-sync] enabled; interval=60s; batch=30; firstRun=5s` 表示已开启；首轮结果及后续有处理记录或错误的轮次写入服务日志。
