# 需求同步时间统一为北京时间

生产库会话时区为系统 CST（实测 UTC+08:00），同步记录使用 `CURRENT_TIMESTAMP` 写入 DATETIME。排查记录 `FRAPPE-DEMAND-20261105101351696-b5cfc919` 的数据库值为 `2026-11-05 18:13:51`，原接口值为 `2026-11-05T10:13:51.000Z`，记录本身正确。

原页面调用 `toLocaleString("zh-CN")`，只设置语言而未固定时区，实际采用浏览器时区；同一时间在 UTC+14 下会显示为 11 月 6 日。无法直接读取用户当前浏览器时区，已用 UTC+14 用例复现跨日现象。

本次修改：

- 需求同步结果、台账、台账明细的 API 时间通过 SQL 格式化并标注 `+08:00`，避免部署服务器时区参与 DATETIME 的解释。
- 页面固定使用 `Asia/Shanghai`，显示 `YYYY-MM-DD HH:mm:ss`，结果区及台账表头标注“北京时间”。
- 兼容原 UTC ISO 返回值和无时区的北京时间字符串；真正到北京时间次日才跨日。
- 不改历史数据库记录、数据库全局时区、同步写入规则或自动同步冷却时间。

无需数据库迁移，部署新构建并重启服务即可。

验证结果：6 个相关测试文件、37 项测试通过，生产构建和 TypeScript 检查通过。本地 5174 已加载修复；最近同步、台账列表及明细 API 均返回带 `+08:00` 的时间。将实际返回数据分别置于 UTC、上海、UTC+14（Pacific/Kiritimati）和墨西哥时区进程中格式化，结果完全一致；核对的最近同步记录显示 `2026-11-05 18:13:51`。登录页 HTTP 200，原有需求单、开票、付款自动同步均正常启用。
