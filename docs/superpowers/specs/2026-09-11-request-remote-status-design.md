# 需求单状态：引入远端履约状态方案

编写日期：2026-09-11

## 一、现状与问题

**本地需求单状态**（`requests.status`）只有三个值，是**采购流程状态**：

| 值 | 触发的动作 |
| --- | --- |
| 草稿 | 保存需求单（`request-order-form-page`）；草稿不进月账单/预付款候选（`req.status <> '草稿'`） |
| 待下单 | 点「确认」后置为待下单，并自动生成采购草稿（`markRequestAsPendingOrder`） |
| 已下单 | 采购订单确认后流转 |

**远端履约状态**有 8 个：Issued to Supplier（采履下发供应商）、Confirmed（采履已确认）、Committed（订单已承诺）、Handed Over（已交单）、Shipped（已发货）、Arrived（已到货）、Received（已签收）、Cancelled（取消）。

两者**不是同一个维度**：本地状态回答"这张单在本地走到哪一步"，远端状态回答"供应商履约到哪一步"。同一张"已下单"的本地单，远端可能处于 Issued to Supplier 到 Received 之间的任意阶段。

## 二、推荐方案：新增"远端状态"字段，双状态并存

**不要**用远端状态替换本地 `status`，理由：

1. 现有采购/财务逻辑（草稿不进财务候选、确认后自动生成采购草稿、删除校验、月度/预付款引用判断）全部依赖本地状态，替换会牵动整条链路，回归成本高；
2. 两个状态不是一一对应，硬合并会丢失信息（无法区分"本地已下单但远端还没下发"和"本地已下单且远端已发货"）。

### 2.1 数据库

`merge_power_requests` 新增：

| 字段 | 说明 |
| --- | --- |
| `remoteStatus` | 远端履约状态（存英文原值，如 `Shipped`） |
| `remoteStatusUpdatedAt` | 该状态最后更新时间 |
| `remoteCancelledItemCount` | 该单被远端取消的明细数（用于"部分取消"提示） |

需求明细 `merge_power_requestitems` 可选增加 `remoteStatus`（逐行状态），便于展开查看。

### 2.2 主单状态的聚合规则

远端状态在**明细行**上，本地需求单是主单，需要定义聚合：

1. 明细按生命周期排序：Issued to Supplier → Confirmed → Committed → Handed Over → Shipped → Arrived → Received；
2. 主单状态 = 该单**所有未取消明细中最靠前**的状态（即"最慢的那条"，代表整单进度）；
3. 全部明细取消 → 主单 `remoteStatus = Cancelled`；
4. 部分取消 → 主单保留原状态，同时记录 `remoteCancelledItemCount`，界面提示"远端已取消 N 条明细"。

### 2.3 展示

- 需求单列表：**保留「状态」（本地流程状态）**，新增「**远端状态**」列（中文展示：采履下发供应商/采履已确认/订单已承诺/已交单/已发货/已到货/已签收/取消）与筛选；
- 需求单详情：两个状态并排显示，远端状态旁标注最后更新时间；
- 状态与本地流程状态**互不影响**：本地状态仍决定能否下单、能否进财务候选。

### 2.4 与采购订单确认的关系（重点）

采购确认目前的做法：需求单点「确认」→ 本地状态变「待下单」并自动生成采购草稿 → 采购单确认 → 需求单变「已下单」。

引入远端状态后建议：

1. **默认不阻断**：远端状态只做展示，不改变现有的"确认 → 生成采购草稿"流程；
2. **增加一条可选校验（建议做）**：采购单确认时，若对应需求单 `remoteStatus = Cancelled` → 阻断并提示"该需求单已被远端取消，请先处理"；若存在部分取消 → 给出警告但允许继续；
3. **取消联动**：远端全部取消时，按上一份方案（`2026-09-11-demand-sync-status-scope-and-cancel-design.md`）在同步台账里提示，并允许对"草稿/待下单且无下游引用"的需求单执行取消。

### 2.5 同步写入位置

同步主流程在写入台账后，按需求单聚合一次远端状态并 upsert 到 `requests`（仅当该需求单已存在于本地；未建档的单不需要）。取消类明细单独计数。

## 三、实施步骤与工作量

| 步骤 | 内容 | 预估 |
| --- | --- | --- |
| 1 | 新增字段 + 迁移脚本（schema/migrate/回滚） | 0.3 天 |
| 2 | 同步侧聚合与写入远端状态、取消明细数 | 0.5 天 |
| 3 | 需求单列表/详情展示「远端状态」列与筛选、中文映射 | 0.5 天 |
| 4 | 采购确认时的远端取消校验（可选） | 0.5 天 |
| 5 | 与"远端取消提示/取消本地单"方案合流实施 | 与上一方案共用 |
| 6 | 试运行核对 + 回归测试 | 0.5 天 |

合计约 **2.5 天**（不含可选第 4 步约 2 天）。

## 四、待确认

1. 「远端状态」列放在需求单列表的哪个位置、是否需要筛选（建议加筛选，候选值就是 8 个状态）；
2. 主单状态聚合规则是否按"最靠前（最慢）的那条"？（另一种是"最靠后（最快）"，但对跟单来说前者更有意义）
3. 采购确认时，远端已取消是否要**阻断**（建议阻断）；
4. 是否需要在需求单明细行上也展示逐行的远端状态。
