# 华为云供应商付款：默认付款单位与数据库编码一致性方案

编写日期：2026-09-11
涉及：`merge_cloud_supplier_payments`、`merge_common_undertaking_units`、`src/lib/cloud-service.ts`、`src/lib/db.ts`

## 一、供应商付款默认「付款单位」

### 1.1 现状

- 供应商付款行由同步按「账期 + 供应商」自动生成（`syncCloudSupplierPaymentPeriods`），付款单位 `payerUnitId / payerUnitName` **默认留空**，只有用户在弹窗里选过才有值。
- 目前库里 1 行付款记录，付款单位已手工选为 **LUZ NEWMEDIA**（`0a1def87-b52d-4408-8fbe-ebf0d4e42fa9`）。
- 承接单位主数据共 6 条，其中含 "LUZ" 的**有 3 条**：

  | ID | 编码 | 名称 |
  | --- | --- | --- |
  | `0a1def87-…` | MXGS01 | LUZ NEWMEDIA（墨西哥） |
  | `13012c23-…` | BRGS01 | Luz 巴西 |
  | `1d4dc8d1-…` | CLGS01 | Z071QP_1（Luz智利） |

  → **不能简单用"包含 LUZ"做匹配**，否则会出现歧义（3 选 1 无法判定）。

### 1.2 设计

**默认值来源**（按优先级）：

1. 环境变量 `CLOUD_SUPPLIER_PAYER_UNIT`：填**承接单位的编码**（如 `MXGS01`）或 ID，最稳、无歧义 —— **推荐**；
2. 回退：环境变量 `CLOUD_SUPPLIER_PAYER_UNIT_KEYWORD` 关键字匹配 `undertakingUnitCode / shortName / entityName`；
3. 匹配结果必须**唯一**，出现 0 条或多条时**不写入**，并在同步结果的告警里提示「默认付款单位未配置或存在歧义」，绝不猜。

**写入时机与规则**：

| 场景 | 行为 |
| --- | --- |
| 同步新建付款行（账期数据首次汇总） | 写入默认付款单位（ID + 名称） |
| 已有付款行且付款单位为空 | 补写默认值 |
| 已有付款行且用户手工选过其它单位 | **不覆盖**（尊重人工选择） |
| 用户在弹窗里清空选择 | 视为"未指定"，下次同步会再补默认值（如需保留空值，需额外加标记，见待确认） |

**历史数据回填**：提供一次性脚本 `npm run sync:cloud-supplier-payments` 之外的小脚本或直接复用同步（同步本身就会补空值），把已存在的空付款单位补齐。

**给外部系统取值**：建议以 **`payerUnitId`** 为稳定键（UUID 不随名称变化），需要可读编码时用 `merge_common_undertaking_units.undertakingUnitCode`（如 MXGS01）关联；`payerUnitName` 仅供展示，不要作为跨系统关联键。

## 二、数据库编码一致性方案

### 2.1 现状与风险

- 本机 `merge` 库：SCHEMA 默认 `utf8mb4 / utf8mb4_0900_ai_ci`，但业务表多为 `utf8mb4_unicode_ci`（**同一库内排序规则混用**）。
- 连接字符集若与库不一致，会出现：① 中文写入变乱码（历史 `suanli` 库那 58 条乱码就是这么来的）；② 唯一键/大小写比较行为不一致；③ 迁移脚本里的中文备注错乱。

### 2.2 建议

1. **连接层显式指定字符集**：在 `src/lib/db.ts` 的 pool 配置里加 `charset: "utf8mb4"`，不要依赖驱动默认值（mysql2 默认是 `utf8mb3`）。这是成本最低、收益最大的一步。
2. **上线前字符集核查脚本**：新增 `scripts/check-charset.mjs`，输出库 / 表 / 列的字符集与排序规则清单，与基线比对，发现非 utf8mb4 立即报警。
3. **统一排序规则（可选，需维护窗口）**：`ALTER TABLE … CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci`，把 `0900_ai_ci` 与 `unicode_ci` 统一（大表耗时，需评估）。
4. **迁移脚本约定**：执行 SQL 时客户端/Navicat 连接字符集必须选 `utf8mb4`；脚本里的中文注释建议**改英文**（避免客户端字符集问题导致备注写入乱码，如 `acceptanceCompletedAt` 注释那样）。
5. **验证方法**：写一个往返测试（插入含中文的值 → 读回逐字节比较），部署后跑一次即可确认生产连接与存储编码一致。
6. **下游对接约定**：明确告知取数方"连接字符集必须 utf8mb4"，并优先使用 ASCII 稳定的 ID/编码字段（如承接单位编码 MXGS01）做跨系统关联。
