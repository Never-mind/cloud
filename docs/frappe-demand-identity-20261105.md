# 远端需求单编号复用修复

远端重建或换环境后可能复用 `DOI-00002` 等编号。以前本地明细 ID 固定拼成 `F-DOI-00002`，与历史需求明细冲突时，新主单和明细会整单回滚。

- 新建明细改用 `F-<UUID>`；历史明细 ID、数量和下游采购关联保持原样。
- 台账保存完整远端快照及来源指纹、远端主单、明细和客户 PO 关联。绑定改变时，把旧快照及本地关联追加到 `sourceDataJson.bindingHistory`。
- 新建成功后刷新比对基线，清除旧的错误和变更提示；失败记录可以正常重试。
- 兼容旧版已建成单据的过期快照：只有已接受的 hash 与当前远端内容一致、台账和实际本地明细都属于当前 PO 时，才归档旧快照并补齐新基线，不改业务单据。
- “重新拉取所选”只处理所选需求单及其使用的映射，全部在同步互斥锁内执行，不再提前重置台账或同步其他需求单。
- 本地已有需求单继续跳过，优先保留有效的明细关联；同编码多条明细不会抢占已有对应关系。
- 定时同步遇到已跟踪但身份变化的远端单据仍提示人工核对，不自动覆盖或重建。人工选中重新拉取才允许重建。

无需修改数据库结构或删除唯一索引。部署更新后的代码、构建并重启服务即可生效。其他仍运行旧代码的服务也需更新后，才能使用修复后的重新拉取逻辑。

回归测试覆盖编号冲突、两张所选单据创建、重复同步跳过、旧快照归档、同步锁冲突、失败回滚、同编码关联稳定性、所选之外的记录不写入。
