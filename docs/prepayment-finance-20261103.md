# 预付款合同开票与收款

合同详情新增“合同明细 / 开票记录 / 收款记录”和按合同币种计算的财务汇总。合同确认及原24个月核销逻辑保持独立，实收台账不参与服务费收入重复累计。

## 使用

1. 先确认合同，在“财务设置”选择合同原金额是含税还是未税，填写百分数税率（无税填0），选择默认客户与承接单位。历史记录不推断税务口径，也不把合同金额当成已收款。
2. “开票记录”可以多次本地开票、发起 Cloud Invoice Process 或国内增值税专票/普票、上传并识别、手动登记已开的发票。每次可以选择不同的客户和承接单位；正式票面保存双方信息快照。手动登记生成的是登记说明，不伪造发票原件。
3. 飞书申请占用本次金额；审批通过后无附件仍是待出票，取得可识别的实际发票后由现有60秒自动任务登记。回票币种、金额与本次申请快照校验，异常留在审批与回票页面，不强行记账。一份申请对应一张实际发票，同一合同可多次申请。驳回/撤销释放占用；已登记票作废后仍保留审批关联，避免轮询重复导入。
4. “收款记录”支持多次收款。默认带出发票未收余额；无可收发票时带出合同未收余额。可修改币种、金额、税率、双方单位、实收日期、是否收款和银行流水号。可先收后开，也可把一笔收款分配至多张发票，或多笔收款关联同一票。
5. 只有有效且“已收款”的记录计入实收。分配只是用于发票余额核对，不会再次增加合同实收。银行流水号可以重复，用于一笔银行转账拆成多条登记。
6. 发票/收款可作废，保留审计记录并回算汇总；发票仍关联有效收款时，先编辑收款解除关联或作废收款。累计开票（包括审批占用）与实际收款各自不能超过合同含税总额；不允许跨合同分配。

## 汇率与关联

- **合同折算汇率**：1张票/1笔款的币种金额 × 汇率 = 合同币种金额。同币种固定为1。
- **发票汇率**沿用系统原有“1 USD 对应原币金额”语义，两种汇率分别保存。
- 收款关联不同币种发票时，另填“1收款币 = N发票币”；每条分配保存票币金额，核对发票未收余额。
- `prepaymentcontracts.financeId`是稳定业务UUID，与可展示的合同号及物理`internalId`分开。已存在票款或审批记录的合同禁止删除、退回草稿，避免破坏核销与财务关系。
- `merge_common_invoice_business_links`保存`sourceType/sourceId/sourceNo`及合同原币折算金额；收款及分配分别存入`merge_common_receipts`、`merge_common_receipt_allocations`。
- 发票预留`importBatchId + importRowKey`唯一键，为将来“一行一票”导入重试幂等使用。后续导入可按`service_fee / cloud_row / prepayment_contract`查找业务来源、调用统一开票服务；本轮不包含Excel批量开票界面。现有账期分摊表继续沿用。

## 部署

在已有发票、飞书审批基础结构的环境上，先备份，再执行：

```powershell
npm run schema:prepayment-finance
npm run schema:prepayment-finance -- --apply
npm run build
npm run start -- -p 5174
```

第一条只输出计划；`--apply`先保存受影响表的建表语句和合同标识/更新时间，再增量添加字段、索引和3张表。只为旧合同补充稳定UUID，保留更新时间，不填历史税率、不创建发票/收款。新表及关联ID明确使用`utf8mb4_unicode_ci`，防止与现有发票表关联时排序规则冲突。备份位于`tmp/prepayment-finance/schema-before-*.json`。

普通部署使用默认`.next`。需要保持旧实例运行进行旁路构建时，可设置`NEXT_DIST_DIR=.next-prepayment-finance`，构建和启动都必须使用相同值；确认新实例正常后再切换端口。该目录已加入忽略列表。

飞书回票继续使用后端启动时注册的自动任务，不新增计划任务。回滚应用时可保留新增结构与业务记录；不要直接删除已有财务数据的表或列。

## 验证

- 单元及旧模块回归覆盖金额计算、审批金额快照、余额阻断、远端失败回滚、附件与回票、原24个月核销。
- `npm run verify:prepayment-finance -- --allow-write-test`只能在`DB_HOST=localhost/127.0.0.1`且库名包含`local`或`test`的隔离数据库运行。使用两张随机UUID测试合同，验证多票多款、跨币种、重复提交、错配阻断、作废、先收后开、审批占用和列表/详情汇总，finally按UUID清理所有测试记录。不得对生产库运行。
- 真实飞书审批发送会触发财务流程，因此自动化测试模拟飞书返回，不替用户发起测试审批。
