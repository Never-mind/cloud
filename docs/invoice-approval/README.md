# 飞书开票审批与回票确认

## 业务入口

- 算力月账单、服务费对账单、华为云对账、集采项目结算沿用统一开票弹窗。
- 一级选择：本地开票 / 飞书审批开票。
- 飞书审批内独立选择 Cloud Invoice Process / 增值税开票申请；切换保留各自草稿，关闭弹窗后不持久化未提交表单。
- 增值税流程支持专票和普票。所属项目组固定 CLOUD，提交飞书的开票金额为人民币含税金额；来源对账单可以是 USD 等其他币种。
- 外币来源单据单独显示来源币种与含税金额；人民币开票金额留空，按客户约定人工填写，不将外币金额按 1:1 直接作为人民币提交。无需为提交审批修改原对账单币种或强制录入汇率。
- 页面不显示审批人员、客户对接人、票据发送办理人等人员选择控件。
- 来源开票弹窗和发票管理的“审批与回票”均可查看审批、同步回票和确认登记。

## 字段映射

| 系统信息 | 增值税申请 | 处理 |
| --- | --- | --- |
| 承接单位全称 | 开票主体 | 与最新飞书选项精确匹配，未命中时人工选择 |
| 客户名称、税号 | 客户公司名称、纳税人识别号 | 从业务伙伴档案预填，可编辑 |
| 客户地址、电话、默认银行 | 专票地址、电话、开户行、账号 | 仅专票必填；多个无唯一默认银行时留空 |
| 来源账期 | 所属月份 | 对应最新飞书月份选项，可调整 |
| 承接单位默认账期 | 账期天数 | 0 天有效；无值时默认 30 天 |
| 来源金额 | 未税、税率、税额、含税 | 人民币来源预填；其他币种仅作参考，人工填写约定人民币金额，税金联动计算，飞书接收人民币含税金额 |
| 当前登录人的飞书绑定 | 必填客户对接人 | 后台填入当前发起人，不显示人员控件 |
| 当前登录人的飞书绑定 | 办理-票据发送节点 | 谁发起就指定谁办理；身份从服务端登录账号读取，忽略前端指定的人员 |
| 当前账期/项目/客户已有附件、本次上传文件 | 附件 | 校验归属后上传至飞书审批附件控件 |

飞书联系人控件的 `value` 仅接收 `user_id`，当前账号绑定的 `open_id` 通过 `open_ids` 传入，`value` 保持空数组。发起人仍使用顶层 `open_id`，办理节点仍使用 `node_approver_open_id_list`，三处均对应当前发起人。不要把 `ou_...` 写进联系人 `value`，否则飞书会按 `user_id` 查找并返回 `1390001: user ... not found`。

各流程选项与字段独立。CLOUD、月份和主体选项每次按飞书当前定义获取，不固定远端选项 key。

## 审批材料

Cloud Invoice Process 与增值税开票申请共用“审批材料”区，可“从单据选择”或“选择文件”，并可混合提交已有附件与本次上传文件。

| 开票来源 | 可选择的已有材料 |
| --- | --- |
| 算力月账单 | 当前月账单附件、开票客户档案附件 |
| 服务费对账单 | 当前服务费对账单附件、开票客户档案附件 |
| 华为云对账 | 当前账期的对账/开票/回款附件、开票客户档案附件；合并时包含所有已选账期 |
| 集采项目结算 | 当前结算单据附件、所属项目的项目附件、开票客户档案附件 |

- 已有附件按来源分组，支持搜索、多选、全选本组和移除；按来源与附件 ID 去重。
- 最多 10 个文件，单个最大 10 MB，总计最大 30 MB。空文件、非法内容、超限文件会被拦截。
- 候选列表只加载元数据；提交时重新检查单据是否存在、合并账期的开票客户是否一致、附件归属及原件是否可读。不会读取任意客户、其他项目或未选账期的附件。
- 所有文件校验成功后才开始上传。飞书上传失败不创建审批，表单和材料保留供修正重试。读取文件或选择材料期间禁止提交、切换流程和关闭弹窗；其他字段的编辑不会被异步读取结果覆盖。
- 两个流程的材料草稿相互独立，切换流程或刷新选项不丢失草稿。关闭弹窗不持久化未提交文件。
- 已有附件保留原存储不变；新文件只用于本次审批，不自动归档到客户/项目附件库。
- Cloud 墨西哥必须明确勾选至少一份“客户 CSF”，可从现有材料选择或上传。补充材料与 CSF 一起传入该流程的附件控件。
- 2026-10-26 只读检查时，Cloud 智利分支没有可见附件控件。该分支仍可无附件发起审批，但附加材料会被明确阻止。需飞书管理员在审批表单顶层添加对智利可见的附件控件；重新打开表单后会按最新定义识别，不会误传到墨西哥隐藏的 CSF 栏。
- 附件使用飞书审批专用上传接口返回的 `data.code`，不接受客户端任意提交云空间文件 token。旧客户附件 ID 入口继续兼容，但执行同样的归属校验。

本功能不需要新增数据库字段。上传通过现有 JSON 路由传输，30 MB 原始文件转为 base64 后约 40 MB；仓库部署文档的 Nginx 示例为 `client_max_body_size 100m`，实际生产代理配置仍需部署时核实。本次模拟 API 验收未验证生产大文件传输。

## 审批与回票

1. 发起审批后保存实例编码、表单快照、来源及合并账期关系。
2. 同步任务读取审批状态、节点状态，以及 timeline / comment_list 的附件。财务可能在前一个审批节点上传发票，不只检查最后的办理节点。
3. 原件下载到系统现有文件存储，保留内容哈希、原始识别结果和识别失败原因。不会只保存会过期的签名 URL。
4. 审批中已回传的发票也能查看；正式登记必须等待审批通过。
5. 用户查看原件，核对/修改票号、日期、双方主体、金额、税率、币种、汇率、账期；再次修改会取消确认勾选。
6. 明确确认后，正式发票、来源回填、附件关联及人工确认快照在同一数据库事务内提交。

增值税回票使用申请快照中的人民币含税金额核对，不直接与美元对账金额比较；识别失败时币种默认 CNY，实际回票币种仍必须为 CNY。币种改变时不沿用原币种开票汇率；登记仅回填开票字段，原应收/实收数据保持独立。

“审批已通过”不等于“已开票”。回票状态独立显示为待回传、已识别待确认、识别失败待补充或已登记。

## 防重与边界

- 同来源的有效审批会阻止重复发起，合并来源使用有序数据库命名锁。
- 同实例相同文件内容仅入库一次；票号和销方税号相同的 PDF/XML/OFD 归组。
- 无法识别的 OFD 可通过文件名中唯一匹配的长票号关联已识别版本，文件名不用于推导金额。
- 版本信息冲突会提示人工核对；原始识别值与人工确认值分别保留。
- 确认时重新同步审批状态，锁定审批/回票/来源，并校验同主体同票号，禁止并发重复登记。
- 已登记结果不会被后续同步覆盖；新补传或换票保留并提示核对。
- 延续当前业务单据一份正式发票的约束。本期不自动处理同一审批拆成多张不同票号、红冲或换票覆盖；这些会被拦截，需先核对原记录。
- 华为云多账期回票金额须与逐期合计到分一致，并保留逐期分摊；有差额时不将整票金额复制到各期。
- 当前识别器支持已有的可解析 PDF/XML/OFD；扫描件或不兼容 OFD 不保证识别成功，可手工确认录入，原件仍保留。
- 下载限制为 20 MB，逐跳验证飞书 HTTPS 域名，不向外部下载地址发送应用令牌。
- 远端创建成功而本地数据库写入失败的跨系统异常，仍需管理员通过飞书实例核对后恢复，不能盲目重试。

## 部署

现有系统已具有飞书审批及发票基础表时，只需要新增回票表：

```powershell
npm run schema:invoice-approval-returns
npm run schema:invoice-approval-returns -- --apply
```

第一条只预览目标和 SQL；第二条执行幂等 CREATE TABLE，不改业务数据。
本机验证可追加 `--local-only`，拒绝非回环数据库地址。
完整飞书审批迁移和新库初始化也已纳入该表。

后台环境配置：

```dotenv
FEISHU_VAT_INVOICE_APPROVAL_CODE=9BF45F81-882F-4C8C-9E7B-E19CC959F294
```

审批 code 可省略，使用上述默认值。当前“办理-票据发送”自选节点由系统自动指定为发起人绑定的飞书 open_id，不再需要固定办理人环境配置，旧的 `FEISHU_VAT_INVOICE_HANDLER_OPEN_IDS` 不再读取。当前账号未绑定有效飞书账号时阻止提交并提示绑定。其他审批节点继续按飞书流程配置，新增的未知自选审批节点仍会拦截，不会擅自指定为发起人。

既有定时任务继续使用 `npm run feishu:approval-sync`，建议每 1-5 分钟执行一批。已通过审批也会轮转检查补传附件。新环境需按现有部署方式配置定时执行；本次开发没有新建后台定时任务，也没有执行真实审批同步写入。

提交/同步/登记要求发票管理创建权限；查看和下载要求查看权限。
