# Cloud Invoice 按确认的 MXN 金额开票

2026-11-11

## 问题与处理

此前多行开票金额使用严格的两位小数字符串校验，额外的小数位或带千分位的粘贴金额会触发“第 1 行请填写有效含税金额”。账期分摊、票面明细和整单金额也需要分别更新；缺少汇率时，调整账期的预填请求可能恢复原币。

本次修改：

- 明细金额统一规范为两位小数，兼容正确的千分位分组和全角数字。明确含义不清的输入（如 `11516,54`）仍提示检查。
- 墨西哥 Cloud Invoice 中直接修改“本期开票含税”，按该行税率反算未税和税金，同步整单合计及唯一对应的票面行。汇率留空时在金额输入完成后反算。
- 飞书明细增加“对应账单（按账号区分）”。按账期生成的行自动绑定具体账单 ID。同月两个账号不再只能按月份猜测对应关系。
- 所有明细都选定账单且覆盖全部关联账单时，“使用明细合计”按对应关系更新账期金额。一个账单允许多条明细；金额合并后填入该账单。
- 对于跨多账单的合并票面行，继续保留上方独立分摊，不猜测账号映射。
- 汇率为参考值，允许实际开票金额与原币乘参考汇率存在差异。提供“按金额反算汇率”，该操作不改变确认的开票金额。零金额或方向不同的金额不能自动推断汇率。
- 后端仍核验整单合计、未税加税金、税率、关联账单权限和审批占用；完整关联的明细还核验每个账号的金额，防止两账号金额互换却因总额相同而漏检。
- 未修改应收原金额、已存在的发票和付款记录，无数据库迁移。

## 本例操作

1. 选择 MXN 和两条 202610 账单。
2. 在对应账号的“本期开票含税”填写 `11516.54`、`92376.13`，核对税率；也可在下方明细中选择对应账单后填金额并点击“使用明细合计”。
3. 系统合计 `103892.67 MXN`。已有汇率可保留作参考；空白汇率自动反算，或点击“按金额反算汇率”。
4. 核对开票内容、客户资料及附件后由用户提交。
