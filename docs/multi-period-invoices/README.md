# 多账期开票与发票分摊

适用：华为云对账单、算力服务费对账单。

## 操作

1. 从任一账单打开“上传并识别”或“开票”。
2. 在“关联账期及开票分摊”点击“选择／调整账期”，筛选月份并勾选同一业务客户的账单。
3. 外部发票只上传识别一次。明确逐月明细且与所选月份、整票金额匹配时采用识别金额，否则按账单金额及汇率分摊，可逐月修改。
4. 本地、Cloud Invoice、增值税审批均可选择“按账期分行”或“合并为一行”。合并一行需要确认服务内容、税收分类可合并；不同税率必须分行。跨年描述如“202512–202605服务费”。
5. USD 账单开 CNY 票时，核对每个月维护的汇率，点击“按账单及汇率填入金额”，可编辑最终分摊。没有汇率时需补填。各期金额合计必须等于整票金额。
6. 一次保存后，同一张发票关联全部所选月份，各月只登记自己的分摊金额，原应收和实收保持原值。

已登记的外部发票：使用“查看／调整本账单已登记发票的分摊”，或在重复票提示中进入“调整关联账期及分摊”。核对全部关联月份后确认替换；保留原主来源账单、整票金额、币种、原件及实际开票双方。本地生成的票如需更改关联范围，需先核对票面并走作废重开。

飞书审批：保存提交时的分摊快照，并自动附上合并开票说明 Excel。Cloud 智利流程没有附件栏时，通过现有备注传达月份、单行要求和分摊。审批通过后继续跟踪回票；识别后由用户核对各月金额并确认登记，不会把审批通过直接当成已开票。实际票面由财务根据申请开具，系统未修改飞书远端审批定义。

## 数据升级与部署

- 新装库的建表脚本已包含分摊快照字段和新的票号索引。
- 已有库先运行 `npm run schema:invoice-allocations` 查看结构差异，再运行 `npm run schema:invoice-allocations -- --apply`。
- 专用升级只执行结构 DDL，不回填业务数据。执行前自动保存两张表的原建表语句到 `tmp/invoice-allocation-schema/`。
- 新增两张主表的 `allocationPlanJson`，审批 `allocationSourceIds` 扩展为 TEXT；以 `(undertakingUnitId, invoiceNo)` 替代全局票号唯一索引。
- 先升级结构，再发布新构建。回滚代码时保留新增字段；若已出现不同主体同号的合法发票，不可直接恢复旧全局唯一索引。
- 测试使用隔离数据与模拟飞书接口，不提交真实审批、不用生产账单做写入测试。

## 处理边界

- 当前一次最多关联 200 条同一业务客户的账单；实际收票客户和开票主体仍可从业务伙伴库另选。
- 已开票或有生效审批的账单会显示原因并禁止重复占用。
- 同一整票只能登记一次；不支持在本入口将一张账单拆到多张不同发票。
- 自动生成的开票说明占用一个审批附件，其他材料最多 9 个。
- 多账期作废会在一个数据库事务内撤销所有月份开票金额及本票附件引用，保留原发票供审计。
